# event-service

Go microservice, port **8082**, gateway prefix **`/api/v1/events`** (`strip_path: false`
in `kong/kong.yml`, so this service handles the full prefix). The `/api/v1/events` route
has **no `jwt` plugin** in `kong.yml` — event browsing is public (rate-limited to 1000
req/min).

It serves the read side of the catalogue: browse events (large or small — the size of an
event is just how many `seats` rows point at it) and read the seat map for one event. It
does **not** yet reserve seats: the seat-reservation saga step (when `booking-service`
publishes `BookingRequested` → this service reserves the seat and publishes
`SeatReserved` / `SeatReservationFailed`) is wired later with `/new-go-api-endpoint`
(a `consume:` + `publish:` step). The
`Seat.Reserve()` / `Seat.Release()` invariants already live on the domain entity so that
step has them to call.

## Layout (Clean Architecture, dependencies point inward)

| Path | Role |
|---|---|
| `internal/domain/` | `Event` / `Seat` entities + invariants (`NewEvent`, `NewSeat`, `Seat.Reserve`/`Release`), `EventFilter` value, `Repository` port, domain errors. No framework/driver imports. |
| `internal/usecase/` | `ListEventsUseCase`, `GetEventUseCase`, `ListEventSeatsUseCase` — one flow each, constructor-injected `domain.Repository`. |
| `internal/adapter/http/` | Handlers, DTOs + `To*Response` mappers, health probes, request-ID / access-log middleware, router. |
| `internal/adapter/repository/postgres/` | `Repository` against Postgres via `pgxpool`, every read in a read-only transaction. Only package allowed to import `pgx`. |
| `internal/platform/` | `config`, `db` (bounded pool + minimal migration runner), `logger` (slog JSON behind an interface). |
| `migrations/` | Embedded `.sql`, applied at startup in filename order. |
| `cmd/main.go` | Composition root + lifecycle (graceful shutdown on SIGINT/SIGTERM). |

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/healthz` | Liveness (no DB touch) |
| `GET` | `/readyz` | Readiness (pings the pool) |
| `GET` | `/swagger/` | Interactive Swagger UI (spec generated by `swag init`) |
| `GET` | `/api/v1/events` | List events, newest first. Query: `upcoming=true`, `limit` (default 20, max 100), `offset` (default 0) |
| `POST` | `/api/v1/events` | Create an event **and its seat map** in one transaction. Body: event fields + a `layout` (see below). `201` returns the event + `seat_count`; `400` malformed body / invalid event / invalid or too-large layout / no seats |
| `GET` | `/api/v1/events/{eventID}` | One event by UUID |
| `GET` | `/api/v1/events/{eventID}/seats` | Seat map for one event, paginated (404 if the event does not exist) |

### `POST /api/v1/events` — seat layout

The seat map is described as a layout the service expands, not a hand-written list — a
100k-seat venue is a ~1KB request:

```json
{
  "name": "...", "description": "...", "venue": "...",
  "starts_at": "2026-09-01T18:00:00Z", "ends_at": "2026-09-01T21:00:00Z",
  "layout": {
    "sections": [
      { "name": "A", "rows": 50,  "seats_per_row": 40, "price_minor": 5000 },
      { "name": "B", "rows": 100, "seats_per_row": 60, "price_minor": 3000 }
    ],
    "exceptions": [
      { "section": "A", "row": "12", "number": "5", "remove": true },
      { "section": "A", "row": "1",  "number": "1", "price_minor": 9000 }
    ]
  }
}
```

Each section generates rows `"1".."rows"` × seats `"1".."seats_per_row"` at `price_minor`.
Section/row/number uniqueness is guaranteed by construction (section names must be unique),
so there is no dedup pass — only `exceptions` are validated: every exception must target a
seat inside the grid, no two may target the same seat, and each must `remove` the seat or
override its `price_minor` (or both). Expansion is capped at `domain.MaxSeatsPerEvent`
(200,000) → `400 ErrLayoutTooLarge`. If every seat is removed → `400`.

Both list endpoints return the pagination envelope, never a bare array:

```json
{ "data": [ ... ], "pagination": { "limit": 20, "offset": 0, "total": 137, "has_more": true } }
```

A non-integer or negative `limit`/`offset` is `400`; an absent one takes the default. `limit`
above 100 is clamped, not rejected.

## What still needs filling in

- `exceptions` currently support `remove` + per-seat `price_minor`. Row-level operations
  (reprice a whole row) and a seat *kind* (wheelchair/companion) would need a `kind` column
  on `seats` first.
- `PATCH`/`DELETE` for events, and adding/removing seats on an existing event — add with
  `/new-go-api-endpoint`.
- Publishing `EventCreated` for `analytics-service` to project — wire with
  `/new-go-api-endpoint` (a `publish:` step) if analytics needs an event read model.
- The seat-reservation saga: consume `BookingRequested`, call `Seat.Reserve()` behind a
  `processed_events` check + row lock, publish `SeatReserved` / `SeatReservationFailed`
  via the transactional outbox — add it with `/new-go-api-endpoint`
  (`consume:BookingRequested:booking.events publish:SeatReserved:seat_reservation`). This
  also adds the `outbox_events` / `processed_events` migrations.
- `docs/openapi/event-service.yaml` + Postman entry — run the `api-doc-sync` agent.

## Testing

Unit tests sit next to the code; every other kind lives in `tests/`, one file per type.

| Type | Where | Real | Faked |
|---|---|---|---|
| Unit | `internal/**/*_test.go` | the code under test | its collaborators: `Repository` (gomock) and the transaction (`FakeDB`) |
| Integration | `tests/integration_repository_test.go`, `tests/integration_kafka_test.go` (`-tags integration`) | our adapter plus a real Postgres / Kafka (Testcontainers) | nothing else |
| Component, in-process | `tests/component_in_process_test.go` (`-tags component`) | the production wiring over real HTTP and a real Postgres | Kafka: events are parsed and handed straight to the use cases; published events are read from the outbox through a test-only trigger |
| Component, out-of-process | `tests/component_out_of_process_test.go` (`-tags component`) | the compiled binary, real Postgres and Kafka, including the seat reaper | booking-service (the test produces its events) |
| Contract | `tests/contract_consumer_test.go` (`-tags contract`) | our event parsing | booking-service, as Pact messages (writes `pacts/`) |
| End-to-end | `tests/e2e_test.go` (`-tags e2e`) | a running stack, through Kong | nothing |

```bash
go generate ./internal/usecase/             # once: the gomock file is generated and not committed
go test ./...                               # unit tests, no Docker
go test -tags integration ./tests/          # needs Docker
go test -tags component ./tests/
E2E_BASE_URL=http://localhost:8000 go test -tags e2e ./tests/

pact-go install -d ~/.pact/lib              # once, for the contract tests
CGO_LDFLAGS="-L$HOME/.pact/lib" go test -tags contract ./tests/
```

Set `TEST_DATABASE_URL` / `TEST_KAFKA_BROKERS` to reuse a Postgres or Kafka you already run. Each
test gets its own throwaway database and topics. The use cases take a `port.Transactor` instead of
the concrete pool so unit tests can hand them a fake transaction. `WriteOutbox` deletes the row it
inserts, so `common.TapOutbox` installs a trigger in the test database that copies every inserted
outbox row into `outbox_tap`; that is how tests see what was published.

## API docs

`docs/` (`docs.go`, `swagger.json`, `swagger.yaml`) is generated and committed. Regenerate
after changing a handler's swaggo comments or a request/response DTO:

```bash
go install github.com/swaggo/swag/cmd/swag@latest   # once, if `swag` isn't on PATH
swag init -g cmd/main.go -o docs
```
